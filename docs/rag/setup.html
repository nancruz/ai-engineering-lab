Set up your lab

Copy the starter package, check it runs, and meet the knowledge base you'll be searching for the rest of the course.

1. Copy the starter

All labs happen in one package, minirag. Copy the starter into projects/ once and work there, so the original stays clean:

$ git clone https://github.com/nancruz/ai-engineering-lab.git
$ cd ai-engineering-lab
$ cp -r tracks/rag/starter projects/knowledge-assistant
$ cd projects/knowledge-assistant
$ python3 -m minirag doctor

doctor shows where the course data is, how far each lab is, and which optional tools it found:

lab                               tests passing
  1. Keyword search (BM25)          0/20   TODOs left
  2. Embeddings & vector search     0/13   TODOs left
  3. Chunking                       1/16   TODOs left
  ...
optional
  · sentence_transformers local embeddings / cross-encoder (Labs 2, 6)
  · fastapi               HTTP API (Lab 7)
  · ollama                not running (optional: local models)

All commands in the course run from projects/knowledge-assistant/ unless a step says otherwise.

2. How a lab works

  1. The module page tells you which functions to write. In the code they look like this: 
    def idf(self, term):
    """Inverse document frequency: rare terms count more. Never negative."""
    # TODO (Lab 1): Implement ln(1 + (N - df + 0.5) / (df + 0.5)) with N = len(self.items).
    raise NotImplementedError("Lab 1: write BM25Index.idf() in minirag/lexical.py")
  2. Each lab has a test file. Run all of it, or just the part you're on with -k: 
    $ python3 -m unittest -v tests.test_lab1_search
$ python3 -m unittest -v tests.test_lab1_search -k Tokenize
  3. When the tests pass, run the experiments on the page. They're the point of the lab: you change one thing, rerun, and look at what moved.
  4. Stuck for more than 20 minutes? Compare with tracks/rag/solution/, which has the same layout.

Labs build on each other. Module 4 uses your BM25 from Module 1 and your chunker from Module 3, so do them in order.

3. Meet the knowledge base

tracks/rag/data/docs/ holds 24 Markdown documents from Lumen, a fictional video-streaming company: runbooks, postmortems, policies, an onboarding guide. They're written to show the problems real RAG systems run into:

Exact identifiersPLAY-4012, CATALOG_DEADLINE_MSKeyword vs vector search

tracks/rag/data/questions.json has 34 questions with labels: which documents are relevant, which passage holds the answer, which facts a correct answer must contain, and which questions must be refused. You'll use them from Module 5.

The front matter at the top of each file is the metadata the system uses:

id: emergency-capacity-settings
title: Emergency capacity settings
status: current        # current | archived
access: sre            # all | sre
updated: 2026-08-18
---

4. Optional: real models

The labs run without any model: there's a hashing "embedder" and an extractive "LLM" that copies sentences. They're deliberately weak, so you can see what a real model adds. Set up one of these whenever you like. Module 2 is the first place it pays off.

Local and free: Ollama

Install from ollama.com, then:

$ ollama pull nomic-embed-text
$ ollama pull llama3.2:3b

Use --embedder ollama:nomic-embed-text and --llm ollama:llama3.2:3b. Any other model you pull works the same way.

Hosted APIs

$ export OPENAI_API_KEY=...
$ export ANTHROPIC_API_KEY=...

Use --llm openai:<model> or --llm anthropic:<model>. For other OpenAI-compatible servers (vLLM, LM Studio, Groq…) also set OPENAI_BASE_URL.

For local embedding and reranking models from Hugging Face: pip install sentence-transformers, then --embedder st:sentence-transformers/all-MiniLM-L6-v2.

5. See where you're heading

The reference solution is a finished system. Ask it something before you start:

$ cd ../../tracks/rag/solution
$ python3 -m minirag ask "What is the current production timeout for catalog API requests?"
──── answer (extractive) ────
Catalog requests use an 800 ms total deadline in production. [S1] The client opens its circuit
breaker when 50% of requests fail across a window of 20 requests within 10 seconds. [S2]

  [S1] catalog-api-timeouts › Deadline
  [S2] catalog-api-timeouts › Circuit breaker

It found the current document, not the archived one that says 3000 ms, and cited the exact section. By Module 4 your own copy will do the same.
